# AG-002 acceptance evidence

This evidence maps the local ticket without altering the preserved backlog or external Linear
state. The orchestrator owns final ticket status.

| Acceptance criterion | Evidence |
|---|---|
| Constraints prevent duplicate SOEIDs/artifact names/grants, invalid ownership, and foreign publication pointers. | Explicit `TB_TA_AGORA_*` project-scoped domain and Django framework tables, Django constraints, Oracle composed-name guards, comparison-key uniqueness, composite foreign keys, lifecycle guards, and PL/SQL triggers in `persistence` migrations; direct ORM-bypass integration tests. |
| Complete Revisions and their Artifacts cannot mutate. | Revision finalization flag is required before commit; exact-one-HTML trigger; post-finalization Artifact insert guard; update/delete rejection triggers and model guards. |
| Artifacts are private and have no raw URL. | `FilesystemArtifactStorage` exposes opaque keys/open/delete only; startup security checks reject static/media, configured static-directory, and installed-app static-directory overlap; content routes remain fail-closed. |
| User filenames cannot control directories or keys. | Logical-name normalization is metadata-only; adapter keys contain 256 random bits and one exact ASCII grammar with shard checks. |
| Writes are atomic, digest-verified, and failure-safe. | Exclusive pending file, streaming SHA-256/size checks, fsync/read-back, atomic no-clobber hard-link install, immutable durable ownership/collision witnesses, ownership-aware compensation, ambiguous-commit/collision fault injection, and cleanup retries. |
| Cleanup is idempotent and root-confined. | Exact-key delete plus bounded `cleanup_artifact_reservations`; reservation row locks settle commit outcomes; only true missing entries succeed; inaccessible/unsafe entries fail closed and retain work; owned or collision bytes are preserved. |
| Empty migrations and collision/traversal/Unicode/partial-write tests pass. | Oracle forward/reverse/forward migration verification, trigger compilation checks, and the canonical `scripts/check.py` gate recorded for this ticket. |

## Required verification

With the documented Oracle profile reachable:

```powershell
$env:AGORA_ENVIRONMENT = "test"
$env:AGORA_TEST_DATABASE_RESET_ALLOWED = "true"
uv run --locked python scripts/check.py
```

Empty-database verification must use a disposable, non-production Oracle schema, apply all
migrations, reverse the `persistence` app to zero, and apply it again. Never use SQLite as a
substitute and never point destructive migration verification at a shared or production schema.
