# AG-002 acceptance evidence

This evidence maps the local ticket without altering the preserved backlog or external Linear
state. The orchestrator owns final ticket status.

| Acceptance criterion | Evidence |
|---|---|
| Constraints prevent duplicate SOEIDs/artifact names/grants, invalid ownership, and foreign publication pointers. | Django constraints plus PostgreSQL ICU canonical-name checks, composite foreign keys, lifecycle guards, and deferred triggers in `persistence` migrations; direct ORM-bypass integration tests. |
| Complete Revisions and their Artifacts cannot mutate. | Revision finalization flag is required at commit; deferred exact-one-HTML trigger; post-finalization Artifact insert guard; update/delete rejection triggers and model guards. |
| Artifacts are private and have no raw URL. | `FilesystemArtifactStorage` exposes opaque keys/open/delete only; startup security checks reject static/media, configured static-directory, and installed-app static-directory overlap; content routes remain fail-closed. |
| User filenames cannot control directories or keys. | Logical-name normalization is metadata-only; adapter keys contain 256 random bits and one exact ASCII grammar with shard checks. |
| Writes are atomic, digest-verified, and failure-safe. | Exclusive pending file, streaming SHA-256/size checks, fsync/read-back, atomic no-clobber hard-link install, immutable durable ownership/collision witnesses, ownership-aware compensation, ambiguous-commit/collision fault injection, and cleanup retries. |
| Cleanup is idempotent and root-confined. | Exact-key delete plus bounded `cleanup_artifact_reservations`; reservation row locks settle commit outcomes; only true missing entries succeed; inaccessible/unsafe entries fail closed and retain work; owned or collision bytes are preserved. |
| Empty migrations and collision/traversal/Unicode/partial-write tests pass. | PostgreSQL forward/reverse/forward migration verification and the canonical `scripts/check.py` gate recorded for this ticket. |

## Required verification

With the documented PostgreSQL service healthy:

```powershell
uv run python scripts/check.py
```

Empty-database verification must create a disposable PostgreSQL database, apply all migrations,
reverse the `persistence` app to zero, and apply it again. Never use SQLite as a substitute.
